# 実装指示：再描画時のちらつき解消（登場アニメーションの再生制御）2026-08-05

対象：`index.html`。lp.htmlは触らない。
背景：竹内さん報告。「カートに反映」等のボタンを押すと、開いているシートが下からもう一度スライドして出てくる（ちらつく）。
原因：状態変更のたびに `render()` が sp-root / pc-root 全体を innerHTML で描き直し（index.html:2981-2982）、オーバーレイのインライン `animation:rk-up/rk-fade/rk-pop/rk-slide` が再生され直すため。
ゴール：**登場アニメーションは「ユーザーが開いた瞬間」だけ再生し、開いたままの再描画では再生しない**。本番実装（差分更新のUI）と同じ見え方にする。

作業前に必ず `git pull`。1タスク=1コミット。

## 実装方針（フラグ方式・全オーバーレイ共通）

1. CSSに1ルール追加：
   `.rk-noanim [style*="animation"], .rk-noanim [style*="animation"] * { animation: none !important; }`
   ※インライン animation を持つ要素とその子のアニメーションを無効化する。セレクタは実装しやすい形に調整してよい（例：sp-root/pc-root に .rk-noanim を付け、`.rk-noanim *{animation:none!important;}` でも可。dd-open等ヘッダードロップダウンも同じ扱いでよい）
2. グローバルに `let ANIM = true;`（次のrenderでアニメーションを許可するか）
3. `render()` の innerHTML 更新直前に：`ANIM` が false なら sp-root / pc-root に `rk-noanim` クラスを付け、true なら外す。innerHTML 更新後に `ANIM = false;` にリセット
4. 「新しくオーバーレイを開く／画面を切り替える」操作の先頭で `ANIM = true;` を立てる。対象（グローバル検索して漏れなく）：
   - 商品モーダルを開く（A._openProduct 等）
   - カートを開く／閉じる、ログインモーダル、検索、ハウツー、通知、マイページ等の各 open 系
   - Area.open（エリア確認モーダル）
   - ページ遷移（S.page の切り替え、雑誌型⇔フルメニュー切替、タブ切替）
   - 開閉トグルの「閉じる」側は true にしなくてよい（消える方向のアニメは元々ない）
5. 「開いたまま状態だけ変わる」操作（カートに反映・数量変更・コイン選択・地域切替・お気に入り等）は何もしない＝ANIM=false のまま再描画され、アニメーションが再生されない

※4で漏れがあっても「アニメーションが出ないだけ」で実害はない（ちらつきより良い）。逆に5に true が混ざるとちらつきが残るので、迷ったら付けない。

## 併せて直すこと（同じ原因の副作用）

- 再描画後のスクロール位置：`render()` で更新前に sp-root/pc-root 内のスクロールコンテナ（あれば）と window のスクロール位置を保存し、更新後に復元する（既にやっている場合は現状維持）
- 商品モーダル内で「カートに反映」を押したときにモーダル内のスクロールが先頭に戻る場合は、それも復元する

## 検証観点（実装後に自分でも一通り確認）

- 商品モーダルを開く→開く瞬間は従来どおりスライドイン→「カートに反映」→**モーダルがちらつかず**、バッジ等だけ変わる
- カート画面で数量変更・コイン選択→画面がちらつかない
- エリア確認モーダル：開く瞬間はアニメあり→S→A→B の遷移中はちらつかない
- 各オーバーレイの初回オープンでアニメーションがちゃんと再生される（全部無効になっていないこと）
