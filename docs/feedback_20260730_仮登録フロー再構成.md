# 実装指示：オンボーディングを「おすすめ提示→仮登録→受付番号」の流れに再構成（2026-07-30）

対象：`index.html` のみ（lp.htmlは触らない）。
背景：基幹の顧客テーブル（KOKYAKU）へ引き継ぐ本人情報を、Webのどの段階で取るか方針決定。
「軽い質問は先、重い入力はおすすめを見せた後。ただし仮注文より前」の並びにする。

※このオンボーディング領域は通常リモート（別端末）優先だが、本件は竹内さん指示により当方で実装する。
別端末エージェントは作業前に必ず pull すること。

## 共通ルール

- 絵文字・装飾記号禁止。既存デザイントークン（#E50012等）・既存のonboardの見た目を踏襲
- 既存機能（エリア判定・7つの質問・taste_profile構築・本体への遷移）を壊さない
- 1タスク=1コミット（日本語・prefix付き）

## 現状（QUESTIONS配列は index.html:2008 付近、レンダは renderStep()）

エリア判定(phase zip) → 7つの質問(step 0-6) → step7で「お名前（ニックネーム）」入力 → data-onboard-finish → buildProfile(name) → 本体へ

## 変更後の流れ

エリア判定 → 7つの質問（変更なし）→ **A. おすすめ提示** → **B. 仮登録フォーム** → **C. 受付番号発行完了** → 本体へ

### A. おすすめ提示画面（step7を置き換え）

- 進捗バーは100%・ラベル「あなたへのおすすめ」
- answers から簡易ロジックでコースを1つ推す：
  - cook_time が「10分以内」→ Cut Meal（カットミール）系、health がカロリー/塩分→ヘルシー系、それ以外→ スマイルミール系（既存CATALOGの名称に合わせる）
- 表示：見出し「あなたにおすすめのコースはこちら」＋コース名＋そのコースのメニューカード2〜3枚（既存カード見た目の簡易版でよい）
- ボタン：「このメニューをはじめる（仮登録へ）」→ B へ
- 下部リンク：「← 前の質問に戻る」

### B. 仮登録フォーム画面

- 見出し「お届けに必要な情報をご入力ください」
- 項目（KOKYAKU対応を意識。*=必須）：
  - お名前*（姓名1欄で可）／フリガナ*
  - 郵便番号*：**エリア判定で入力済みの値を転記済み**で表示（編集可）
  - ご住所*（市区町村・番地。1欄で可）
  - 電話番号*：下に小さく注記「ご本人確認とお届けのご連絡に使用します」
  - メールアドレス*／パスワード*
  - 生年月日（任意・date入力可）
  - ご家族の人数：大人・子ども の2つの数値select。**質問1（何人分）の回答から初期値を転記**（2人分→大人2子0、3人分→大人2子1、4人分以上→大人2子2。編集可）
  - ご紹介者コード（任意・6桁）
- バリデーションはモックなので簡易（必須が空なら登録ボタン無効 or アラート）でよい
- ボタン「仮登録する」→ C へ。「← おすすめに戻る」リンク

### C. 受付番号発行完了画面

- 見出し「仮登録が完了しました」
- 受付番号を大きく表示：`R-260730-001` 形式の固定値でよい（採番ロジック不要）
- 注記2行：
  - 「担当営業所で確認後、本登録のご案内をお送りします」
  - 「いまから仮のご注文が可能です。お届けは本登録完了後に確定します」
- ボタン「メニューを見る」→ 従来の data-onboard-finish 相当の処理（buildProfile は B の氏名を渡す）→ 本体へ

### その他

- LPの「無料ではじめる（かんたん7つの質問）」の文言は変更しない（質問数は7のまま）
- buildProfile(name) の name は B のお名前を使用。answers の扱いは既存のまま
- B で入力した値は sessionStorage 等に保持しなくてよい（モック）
