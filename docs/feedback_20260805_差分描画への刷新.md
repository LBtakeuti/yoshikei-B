# 実装指示：全画面ちらつきの根本解消＝innerHTML全置換をDOM差分更新に刷新（2026-08-05）

対象：`index.html`。lp.htmlは触らない。
背景：竹内さん報告（2回目）。カートに反映に限らず**あらゆる操作で画面全体がちらつく**。652b92bのアニメーション抑制では不十分。
根本原因：`render()` が毎回 `sp-root.innerHTML = spHTML()` で**DOM全体を破棄・再構築**しているため、既存の要素（特に画像）が作り直され、再ペイントの瞬間が見える。
ゴール：**本番実装（React等の差分更新）と同じ見え方**。変わっていない要素はDOMノードを使い回し、変わった部分だけを更新する。

作業前に必ず `git pull`。1タスク=1コミット。

## 実装方針：軽量DOMモーフ（morphdom方式・自前実装で可）

`render()` の `root.innerHTML = html` を `morph(root, html)` に置き換える：

```js
function morph(rootEl, html){
  const tpl = document.createElement('template');
  tpl.innerHTML = html;
  morphChildren(rootEl, tpl.content);
}
function morphChildren(from, to){
  // 子ノードを先頭からインデックス対応で同期
  // 1. to側が多い→appendChild／from側が多い→末尾から削除
  // 2. 同位置ノード同士：
  //    - nodeType や tagName が違う→replaceWith(新ノード)
  //    - テキストノード→ textContent が違うときだけ代入
  //    - 要素→ syncAttrs(既存, 新) してから morphChildren(既存, 新) へ再帰
}
function syncAttrs(el, newEl){
  // newElにある属性をすべてel側へ（値が同じならskip）。elにしかない属性は削除
  // 例外：
  //  - input/textarea/select が document.activeElement のときは value/checked を上書きしない
  //  - img は src が同じなら触らない（別srcのときだけ差し替え）
  //  - value属性は property(el.value) も同期（フォーカス外のとき）
}
```

### 必須の性質

- **同じ画面状態の再描画では、imgノードが再生成されない**こと（これがちらつき解消の本体）。検証方法：操作前に `document.querySelector('img.○○').dataset.keep='1'` を付け、操作後も残っていることを確認
- インラインstyle・class・onclick等の属性は毎回同期する（挙動は従来と同一に保つ）
- 構造が大きく変わる場面（ページ遷移・オーバーレイの出現/消滅）は replaceWith で従来どおり作り直しになって構わない（そこは登場アニメーションが再生されるべき場面でもある）
- SVG要素（カルーセル矢印・アイコン類）は createElementNS の扱いに注意。tagName比較は大文字小文字を吸収する（template内のSVGはそのまま比較でよいが、名前空間はcloneで維持される）

### ANIM（652b92b）の扱い

- ANIM/rk-noanim の仕組みは**そのまま残す**（差分更新でも、稀にノード再生成が起きたときの保険になる）
- anim() を立てる箇所も現状維持

### スクロール・フォーカス

- ノードを使い回すため、[data-sc] の保存・復元は原則不要になるが、既存機構は壊さず残してよい
- フォーカス中の入力欄は value を上書きしない（syncAttrsの例外で担保）

## 検証観点（実装後に自分でも一通り）

1. 商品モーダルを開いたまま「カートに反映」「数量±」→ モーダル・背面とも一切ちらつかない。モーダル内のimgが同一ノードのまま
2. 雑誌型トップで地域切替チップ・お気に入りトグル → メニュー棚の画像がちらつかない（imgノード維持）
3. カートで数量変更・コイン選択 → ちらつかない
4. ページ遷移（トップ→カート→マイページ）・オーバーレイ初回オープン → 従来どおり表示され、登場アニメーションも再生される
5. 検索・ログイン・エリア確認モーダル（静的DOM側）が従来どおり動く
6. E2E既存シナリオ（注文動線・仮登録動線）が通る
