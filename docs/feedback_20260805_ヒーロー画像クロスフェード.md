# 実装指示：ヒーローセクションに実写真2枚のクロスフェード（2026-08-05）

対象：`index.html`。lp.htmlは触らない。
画像（配置済み・未コミット。同コミットに含める）：
- `assets/hero-1.png`（子どもが食事している写真・1200×600）
- `assets/hero-2.png`（親子で料理している写真・1200×600）

竹内さん指示：ヒーローセクションでこの2枚を**6秒ごとにフェードイン/アウトで交代**（移り変わり）させる。

作業前に必ず `git pull`。1タスク=1コミット。

## 仕様

1. 未ログイントップ（雑誌型）のヒーローセクションの背景を、この2枚のスライドショーにする。SP・PC両方
2. 実装は**CSSキーフレームのみ**で行う（JSタイマー禁止）：
   - 2枚の img（または background の div）を絶対配置で重ね、`object-fit:cover` で領域いっぱいに表示
   - 12秒ループのopacityアニメーション。1枚あたり約6秒表示、切り替わりは約1秒のクロスフェード（例：hero-1=0%〜46%表示→50%で消える／hero-2はその逆位相）
   - 理由：差分描画（morph）でノードが使い回されるため、CSSアニメーションなら再描画の影響を受けず動き続ける
3. **rk-noanim との干渉に注意（必須）**：`.rk-noanim,.rk-noanim *{animation:none!important;}` がヒーローのクロスフェードまで止めてしまう。ヒーローのスライド要素は除外すること（例：noanimルールを `.rk-noanim *:not(.hero-slide)` にする、またはより後方で `.hero-slide{animation:...!important;}` を宣言して同詳細度・後勝ちで上書き）。**rk-noanimが付いた状態でもクロスフェードが止まらない**ことを必ず確認
4. ヒーロー上のテキスト・CTAボタン等の既存要素は最前面に維持（可読性が落ちるなら写真の上に薄い白〜クリームのオーバーレイgrad（例：rgba(255,251,244,.55)〜透明）を1枚挟んでよい。文字が読めることを優先）
5. ログイン済み画面・他ページには影響させない
6. prefers-reduced-motion の既存ルール（index.html:45付近）配下では静止（hero-1固定）になって構わない

## 検証観点（実装後に自分でも確認）

- SP/PCともヒーローで2枚が約6秒周期で入れ替わる（フェードの重なりが自然）
- カートに反映・地域切替など再描画後もフェードが止まらない・リセットされない
- ヒーロー内の見出し・ボタンが読める／押せる
- 雑誌型→フルメニュー→戻る、でヒーローが正常に再表示される
