- お客様提供の実メニュー写真（581×400）。末尾の数字=曜日番号（1=月〜6=土）。画像登録マニュアルの「メニュー名2文字コード」に対応

目的：イメージ喚起。プレースホルダー（assets/noimage.png）の海から脱して、実際の商品写真で画面の説得力を上げる（竹内さん指示）。

作業前に必ず `git pull`。1タスク=1コミット。

## 仕様

1. **画像解決ヘルパーを追加**：`menuImg(seriesName, dayIndex)` のような関数で、シリーズ名→2文字コードの対応表（`MENU_IMG_MAP`）を引き、`assets/menu/<code>/<code><day>.jpg` を返す。該当なしは null → 従来どおり `slot()`（noimage）にフォールバック
2. **コード割り当て**：SERIES 配列（Smile＆tableのsubs）の**露出が多い主要3シリーズ**に AA・CC・DD を割り当てる（例：定番系=AA、カット野菜系=CC、もう1系=DD。実際のシリーズ名はコード内のSERIES定義を見て決め、`MENU_IMG_MAP` にコメントで対応を明記）
3. **曜日対応**：曜日を持つ商品（週次夕食）は 月=1〜土=6 で対応する画像を使う。曜日概念がない画面（棚のカード等）は商品のインデックスや曜日既定値で1〜6を循環させ、**同じ商品には常に同じ画像**が出るようにする（ランダム禁止・再描画で変わらないこと）
4. **適用箇所**（noimageのslot()を置き換える箇所。網羅的に）：
   - 未ログイン雑誌型トップの「今週のメニュー棚」（6品）→ 6枚で一番映える組み合わせに
   - メニュー一覧（シリーズタブ・グリッド・配達日ビュー）
   - 商品詳細モーダルのメイン画像
   - カート内サムネイル・レコメンド（もう一品）・お気に入り
   - 対応コードがないシリーズ（Lovyu・単品等）は従来どおりnoimage
5. **表示**：既存の `object-fit:cover` を踏襲（アスペクト比581×400なのでカードでもきれいに収まる）。alt は商品名
6. **差分描画との整合**：morphでimgノードが使い回されるため、同一商品で src が変わらないこと（3の「常に同じ画像」が担保になる）

## 検証観点（実装後に自分でも確認）

- 雑誌型トップの棚6品に実写真が出る／フルメニュー・詳細モーダル・カートにも出る
- 対応外シリーズはnoimageのまま崩れない
- 再描画（カート反映・地域切替）で画像が入れ替わったりちらついたりしない
