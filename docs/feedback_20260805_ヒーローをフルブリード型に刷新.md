## 仕様（hero-patterns.html のパターン1を移植ベースにする）

1. 現行の「左クリーム＋右写真パネル＋スクリム」の構造を撤去し、**写真をヒーロー領域全面に表示**（SP・PC両方。object-fit:cover）
2. 下部に暗めのグラデーション：`linear-gradient(0deg, rgba(0,0,0,.55) 0%, rgba(0,0,0,.18) 38%, rgba(0,0,0,0) 62%)`
3. テキストは左下に白抜きで配置：受付中バッジ（赤地白字・従来の文言）→ キャッチ「つくる人から、笑顔に。」（Zen Maru Gothic 900・白・text-shadow 0 1px 10px rgba(0,0,0,.35)）→ サブ文 → CTA「今週のメニューを見る」（赤ピル・従来の遷移先）→ 締切表示（白85%）
4. **4枚ローテーション**：hero-1→2→3→4 の順。1枚あたり約6秒表示・約1秒クロスフェード＝**24秒ループ**。CSSキーフレームのみで実装（JSタイマー禁止）
   - 背景が透けない構成にする（例：hero-1を土台に常時表示し、hero-2/3/4をそれぞれ位相をずらしたopacityアニメーションで重ねる。各スライドのkeyframesは25%区切りで6秒表示+フェード）
   - 全スライドに `.hero-slide` クラス（rk-noanim除外の対象。既存の `:not(.hero-slide)` 除外が効くこと）
5. 高さ：SP=現行ヒーローと同程度（画面を占有しすぎない）／PC=340〜400px程度。文字が写真の顔に重ならないよう object-position は画像ごとに調整してよい（hero-3は被写体が右なので左下テキストと好相性）
6. prefers-reduced-motion では hero-1 で静止
7. ヒーロー直下のエリアバナー・バナーカルーセル以降の構成は変更しない
8. 旧スクリムCSS・旧構造の残骸（.echero-scrim等、不要になるもの）は削除

## 検証観点（実装後に自分でも確認）

- SP/PCとも写真が全面に出て、24秒で4枚が一巡する
- 白テキスト・CTAが4枚すべての上で読める（特にhero-3の明るい木目の上でも下部グラデで読めること）
- カート反映等の再描画でフェードが止まらない
- 雑誌型→フルメニュー→戻る で正常
