2. ヒーロー直下に単独配置していたエリア確認バナーは**撤去**し、その画像を**試験的にカルーセルの1枚として手動で組み込む**（管理画面の代わりに開発側でハードコード）

作業前に必ず `git pull`。1タスク=1コミット。

## 仕様

### 1. カルーセルの2:1化
- バナースライドの枠を `aspect-ratio: 2 / 1` に統一（SP・PC両方）。既存の高さ指定は撤去
- SP：幅は現状どおり（コンテンツ幅）。高さは自動で幅の1/2になる
- PC：2:1にすると現状幅（最大1200px）では高すぎる場合、**アクティブバナーの幅を720px前後に縮めて中央寄せに調整してよい**（比率2:1は厳守。矢印・ドット・スワイプの既存挙動は維持）
- 既存バナー（trial/shelf/coin のプレースホルダー3枚）も同じ2:1枠で表示されること（中身のレイアウトは枠に合わせて調整可）

### 2. エリア確認バナーをスライドに統合
- カルーセルの**先頭スライド**として追加：画像 SP=`assets/area-banner-sp.png`／PC=`assets/area-banner-pc.png`（1774×887=ちょうど2:1）。alt="お届け対象エリア内か確認する"
- タップ/クリックで `Area.open()`（他バナーのhref遷移ではなくモーダル起動）
- **エリア確認済み（rk_area_checked）のときはこのスライドをカルーセルから除外**（他のスライドだけで回る）
- **ヒーロー直下の単独エリアバナー（abn-hero）は削除**（コード・CSSとも残骸なし）
- SP下部の追従バナー＋ピルは変更しない

### 3. 差分描画との整合
- スライド構成が変わる（確認済みで1枚減る）ため、スライドに `data-mk` を付与して隣が巻き添え再生成されないようにする
- カルーセルのイベントバインド（__bnrBound）とドット数の追従が正しく動くこと

## 検証観点（実装後に自分でも確認）

- SP/PCともカルーセルの全スライドが2:1で表示。先頭がエリア確認バナー画像
- 先頭スライドのタップでエリア確認モーダルが開く。9300000→B→進む後はスライドが消え、ドット数も減る
- 2枚目以降（お試しキャンペーン等）のタップ遷移は従来どおり
- スワイプ・矢印・自動送り・ドットの回帰。横スクロールなし
- ヒーロー直下に単独バナーが存在しない

## 追記（2026-08-06 竹内さん追加指示）

- スライドの切り替えは**左右スライドではなくフェードイン/フェードアウト**（参考：メディア・ワーク社サイトのヒーロー）。
- 実装：全スライドを2:1ステージに absolute で重ね、表示中の1枚だけ `.on`（opacity:1）。opacity .7s のクロスフェード。
- 自動送り5秒・ドット・PC矢印・スワイプ（横フリックで送る）は維持。現在位置はBannerモジュールが一元管理し、差分描画後に `.on` を付け直す。
